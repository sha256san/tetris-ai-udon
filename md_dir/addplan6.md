# Executive Summary  
本調査では、**25個の特徴量**を用いたテトリス着地候補の評価関数を設計し、T-Spinドネイトや連続火力を生かせる強力なAIの構築を目指す。まず既存の評価関数研究から、**「穴（ホール）・凸凹度・高さ・消去ライン数」**などが主要特徴量であることが分かっている。本報告ではこれらをベースに、T-Spinやドネイト、ダウンスタック性などを捉える新規特徴量を加えた25特徴量を定義する。各特徴量については計算式・正規化・期待値範囲・重要度を明示し、二重計上や冗長性を分析して統合案を表形式で示す。

さらに、評価関数の構造として**線形結合モデル**にとどまらず、**二次項・対数項・閾値ステップ・シグモイド・木構造モデル**など複数の非線形混合モデル候補を検討する。各モデルの数式例と擬似コード、GPU実装時のコスト課題も示す。また、現在のリアルタイム**ルールベース補正（ヒューリスティック）**との併用方法も整理し、衝突解決の方針を提案する。特徴量の**正規化・スケーリング**には min-max、Zスコア、ロバストスケーリングなどを検討し、重み学習時の**勾配クリッピング・L2正則化・重み初期値**戦略も議論する。学習/チューニング手法として自己対戦（特に強化学習・MCTS）、進化戦略（GA/CMA-ES）、ベイズ最適化、差分進化、Population Based Training（PBT）を挙げ、評価指標とA/Bテスト設計にも触れる。

最後に、既存の20特徴量モデルから新25特徴量モデルへの段階的移行手順を策定し、ロールバック条件を定義する。成果物として、**特徴量定義表（Markdown・CSV）**や**評価パイプライン図（Mermaid）**、上位特徴量3～5個の**実装コード例（Python/Numpy/PyTorch）**と単体テストも提示する。提案内容は、学術文献・実装ガイドライン・コミュニティ情報（テトリスガイドライン、TETR.IO仕様、shiwehi.com等）を踏まえて分析的にまとめた。なお、必要箇所では以下の文献等を参照している。

| CoveredHoles         | HoleCount, AggregateGap と関連: **AggregateGap**に統合検討。  |
| HoleDepthSum         | 深さ指標: 他穴特徴量との相関高。<br>「総穴リスク」ひとまとめも可。       |

## 3. 評価関数のモデル候補（線形・非線形）  
25特徴量を組み合わせる評価関数のモデルとして、次の候補を検討する。各モデルについて**数式例・擬似コード・GPU実装留意点**を示す。実効性・計算コスト・実装容易性を考慮し、モデルA～Eを提示する。  

1. **モデルA（重み付き線形合成）**: 従来型の**線形評価関数**。各特徴量に重みを乗じて線形和を計算する。  
   \[ \mathrm{Score} = \sum_{i=1}^{25} w_i f_i \]  
   - *擬似コード*: `score = 0; for i in features: score += w[i] * f[i]`  
   - *特長*: 単純でGPU高速処理適。重み最適化は凸最適化/進化的手法で容易。多くの既存TetrisAIや強化学習論文で採用済。  
   - *注意点*: 完全線形では**非線形効果**（閾値処理や相互作用）を捉えにくい。`HeightRisk`のように高次項を別設計するか、後述のモデルC等で補う。  

2. **モデルB（線形＋二次項）**: 主要特徴量の二次項や相互項を加える**二次モデル**。  
   \[ \mathrm{Score} = \sum_i w_i f_i + \sum_i v_i f_i^2 + \sum_{i<j} u_{ij} f_i f_j \]  
   - *擬似コード*: `score=0; for i: score+=w[i]*f[i]+v[i]*f[i]*f[i]; for i<j: score+=u[i][j]*f[i]*f[j]`  
   - *用途*: 特定特徴の**飽和効果**（例: 高さが大きいほどペナルティ急増）や、`HeightRisk = (h>θ)^2`のような効果を自然表現できる。特徴間の**相互影響**（例: 高さ×穴）も評価可能。  
   - *計算量*: 二次項追加で計算量O(n^2)増。重み数増加でチューニング複雑化。GPUではテンソル演算で並列化可能だが、学習安定化が課題。  

3. **モデルC（piecewise／閾値関数）**: 特徴量を**区分線形/ステップ**で扱うモデル。  
   例: \(\mathrm{Score} = \sum_i w_i f_i + W_h \cdot \max(0, h_\mathrm{max}-\theta)^2\) のように、`HeightRisk`を閾値を越えた場合に重み付与。  
   - *擬似コード*: 
     ```python
     score = sum(w[i]*f[i] for i in features)
     if max_height > theta:
         score -= penalty_coef * (max_height - theta)**2
     ```  
   - *用途*: 高さや穴など**危険領域で急激なペナルティ**を実現。ログやシグモイドより直感的。例えば「高さ20で即死ペナ」などのルール反映に有効。  
   - *注意点*: 条件分岐が入りやすく、GPUでは分岐コストに注意。小分子演算に限定しないと**分岐のオーバーヘッド**がある。  

4. **モデルD（Log/Sigmoid 混合）**: 特徴量の**非線形マッピング**を導入。例えば高次の特徴を \(\log(f+1)\) や \(\mathrm{sigmoid}(f)\) 変換して重み付けする。  
   - *数式例*: \(\mathrm{Score} = \sum_i w_i f_i + \sum_j v_j \log(f_j+1) + \sum_k u_k \sigma(\alpha f_k + \beta)\)。  
   - *擬似コード*: `score = sum(w[i]*f[i]) + sum(v[j]*log(f[j]+1)) + sum(u[k]*sigmoid(alpha*f[k]+beta))`  
   - *用途*: 大きな値を**緩やかに飽和**させる。例えば高さや穴数の増加に対する追加ペナを緩和し、バニシング・ポイントを設定。シグモイド系活性化はニューラルネットの利点を借りるイメージ。  
   - *注意点*: 対数・シグモイド演算は非線形で、実装は簡易だが微分学習時の**勾配消失**に注意。GPU向けのベクトル演算ライブラリで効率化可能。  

5. **モデルE（ツリーベース／学習混合）**: 特徴量を**非線形木構造**や小規模ニューラルネットで組み合わせる。  
   - *例1*: **決定木/GBDT**: 特徴量範囲で分割しスコアを返す。単体の探索AIには重いが、強化学習の価値関数やパラメタ探索の参考に。  
   - *例2*: **小規模ニューラルネット**: 25入力 → 1出力 (1層または2層MLP)。例として、Elfwingらはスワッシュ活性化NNで小盤面TetrisにてSOTA達成。  
   - *擬似コード*: PyTorch等で全結合層を定義し、`score = Net(features)`.  
   - *用途*: 線形では表現困難な**複雑な非線形効果**を学習できる。例えばT-Spin構造の相互作用を内部で表現可能。  
   - *注意点*: 計算コストと学習の安定性が課題。GPUでは行列演算で高速化できるが、重みの初期値・正則化・学習率調整が重要。デプロイ時の推論レイテンシも考慮する必要がある。  

**GPU実装上の留意点**: モデルA～Dの線形・分岐・対数・シグモイド操作は全てベクトル演算で実装可能。特に線形結合は行列積で一括演算が可能で高速化できる。モデルCの条件分岐はブランチ予測ミスが懸念されるため、工夫してフラグ操作やマスクを用いるとよい。モデルEのニューラルネットは一般的な深層学習同様にGPU最適化ライブラリを利用できるが、小規模ネットワークであれば重みの数を抑えることも検討する。  

## 4. リアルタイムヒューリスティックとの併用  
既存AIでは**ヒューリスティック補正**を並行して用い、微調整や安全策を講じる。例えば、以下のようなルールベース補正を提案する：  
- **中央凸凹ペナルティ**: 盤面中央（列4~5など）に突出した山が形成されると、後続のIミノ活用が困難になるため大きめのペナルティ（例：凸凹度×-40）とする。  
- **両端同時空きペナルティ**: 両端が空いてIミノ待ち状況は、I枯渇リスクが高いため厳しく評価（例：空端の严重度×-60）。  
- **新規Tスロット構築ボーナス**: 着地後に3～8列目に新たなT-Spinスロットができた場合、大きく加点（例：+60×列品質）し、T-Spin連鎖を誘導。  
- **階段ドネイトボーナス**: 特定の階段状配置（STMB Cave, Parapet等）を形成した場合、+45点程度を付与。  
- **実戦T-Spinボーナス**: 実際のT-Spin着地に応じて追加点を付加（例：TSD+140、TSS+40、TST+180、逆向きTSTは-100など）。  
- **T-Spin空打ち・ミニ罰則**: 何もしないT-Spin、MiniT-Spinはマイナス（例：-60、-30）。  
- **背面TST（Reverse Wall TST）ペナルティ**: 特定リスク構造の回避（例：-80）。  
- **埋め込みドネイトペナルティ**: 下穴になるようなドネイトは穴数×-25のペナルティ。  

これらは上記評価関数で数値化しづらい**例外的なケース**に対する修正として利用する。実装上は、「探索候補を評価した後、該当ヒューリスティック条件があればスコアに加算/減算」する形とする。優先順位の高いヒューリスティック（死活直前の禁止行動など）を先に適用し、残りは線形スコアに加えることで、**探索結果を微調整**する。衝突解決は、優先度の低いルールを後付けでオーバーライドさせないよう、明示的に**「罰則は総和」**で処理するか、場合によっては**大きなマイナス∞**で候補を除外する（緊急回避の場合）。こうした補正は、人間プレイヤーが戦術を決める際に行う暗黙ルールであり、AIにも安全装置として有効と考えられる。  

## 5. 正規化・スケーリングと学習安定化  
特徴量間のスケール差が大きいため、**正規化**は必須である。一般的手法として以下を採用・比較する：  
- **Min-Max正規化**: \([0,1]\)範囲に線形変換。実装簡単で解釈しやすいが外れ値に弱い。特徴量ごとの最大値は盤面20×10の論理上限（高さ200など）で決定できる。  
- **Z-スコア正規化**: 平均0・分散1に変換。値の中心化・標準化に有効。訓練データで平均・分散を推定し、オンライン学習では移動平均で更新する。  
- **Robustスケール**: 中央値・四分位範囲を用いる手法で、外れ値頑健。穴数や高さ変化の極端なケースがあるため、ロバストスケーリングも検討する。  
- **ランク/順序正規化**: 各特徴値を0～1の順位に置き換え。非線形だが外れ値に完全に強い。特徴量間の線形関係は失うため、最終手段。  

どの方法でも**各特徴量が同程度の重み付けスケール**になるよう調整する。深層学習ではバッチ正規化やLayerNorm、データ拡張なども使えるが、探索的評価関数では上記基本形を用いる。  

学習・チューニング時の**安定化手法**としては、主に以下を挙げる：  
- **勾配クリッピング**: 重み学習やニューラルネット訓練での発散防止。勾配ノルムを上限(例:1.0)にクリップする。PolyMechのTetrisガイドでも推奨例としている。  
- **L2正則化**: 重みの大きさを制限し、過学習を抑制。特に線形モデルの重み学習で効果的。  
- **重み初期化レンジ**: 各重み初期値は小さめに設定（ガウス分布𝜎=0.01程度など）。大きすぎると最初の評価関数が偏る。バイアス項は0スタートか小さな定数にする。  
- **バッチ正規化/入力正規化**: ネットワーク利用時は層正規化などを併用し、特定特徴が支配的にならないようにする。  
- **学習率調整**: 高次の重みや非線形項追加時は、小さな学習率から始める。Adamなど適応学習率法も有効。  
- **Early stopping**: 学習曲線モニタリング中、過学習兆候が出たら打ち切る。自己対戦学習では一定試行ごとに評価。  

これらにより、評価関数学習（強化学習／進化学習）時の**安定かつ高速な収束**が期待できる。PolyMechのTetris手法でも、「勾配クリッピング」「価値関数正規化」等で安定性を確保していることが報告されている。  

## 6. 学習・チューニング手順と評価指標  
**学習手法**としては、以下の組み合わせを検討する：  
- **自己対戦強化学習**: ポリシー最適化 (例: PPO, A3C) や最良木探索（MCTS）と組み合わせる手法。価値関数の初期候補として前述評価関数モデルを入れ、自己対戦で改善するアプローチ。特徴量版AIではActor-Criticを用いる例が多い。  
- **進化戦略／遺伝的アルゴリズム (GA)**: 25個の重み/パラメータを個体として最適化。各個体をシミュレーションプレイで評価し、交叉・突然変異で更新する。GAやCMA-ESは**探索高次元連続空間**に強く、Tetris評価関数の重み調整にも適用されている。ErcanらはGAで穴/凸凹特徴を動的重み付けし大幅な性能向上を示した。  
- **ハイパーパラメータ最適化**: ベイズ最適化や差分進化(DE)で、重み以外のパラメータ（正規化スケール、閾値、学習率など）を探索する。適応的に行うPBT（Population Based Training）も、モデル更新と並行して重み遺伝子を交換・突然変異する手法として有望。  
- **教師付き/模倣学習**: 優れたプレイヤーのプレイ記録や、高性能AIのプレイデータを用いて評価関数を学習する方法。汎用性が課題だが、初期値設定や特徴量重みのプリトレーニングに活用できる。  

**評価指標**: AI性能の比較には複数指標を用いる。例としての改善割合を踏まえつつ、以下を測定すべきである。勝率や消去行数だけでなく、**T-Spin獲得率・B2B継続回数・連鎖数・平均穴数・決定時間**など多角的に評価する。具体例:  
1. **平均消去ライン数 (Lines Cleared)／PPS**: 積極的攻撃力を示す基本指標。  
2. **Top-out率**: ゲームオーバー率。  
3. **T-Spin回数・成功率**: T-Spin撃ちやTSD/TSS回数と成功率。  
4. **B2B平均長**: Back-to-Back連続回数。  
5. **REN長**: 連鎖（REN）最大長・平均長。  
6. **Perfect Clear回数**: PC達成数。  
7. **平均穴数・平均高さ**: 防御面を測る。  
8. **平均ホールド回数**: ホールド活用度。  
9. **APM**: 秒間移動回数（操作量）。  
10. **意思決定時間**: 遅延許容評価。  
評価には統計的有意性を確保するため、各設定で**複数（数十～百以上）のゲーム**を実行し、A/Bテスト（制御群=旧モデル vs 実験群=新モデル）で比較する。たとえばユーザー間A/Bでは、α=0.05, β=0.8の水準で最小必要サンプル数を算出し、検定する。ゲームでは「1試行=1ゲームとみなして平均と分散を計測」する方法も多い。

## 7. シミュレーション実験計画  
**ベースライン**として、現行の20特徴量モデル（既存`model.json`相当）を使用し、新25特徴量モデルと比較する。実験変数は**評価関数モデル**（A～E）と**重み/ハイパーパラメータ群**、**ヒューリスティックルールの有無**など。評価の流れ：  
- **条件設定**: (a) 線形モデルA vs 他モデル、(b) 25特徴量 vs 20特徴量、(c) ヒューリスティック有/無、(d) 学習/重み最適化手法（PPO vs GA vs CMA-ES vs PBT）等。  
- **シミュレーション実施**: 各条件下で**100～500ゲーム**程度をプレイし、各評価指標を集計。重要指標は試行ごとの結果分布（平均・σ）で確認する。  
- **統計検定**: 対照群（基準モデル）との比較にはt検定やU検定を用いる。例: 「平均ライン数」「T-Spin数」「Top-out率」それぞれに対してp値を求め、実質的効果量（Cohen’s d等）も報告する。  
- **期待効果量**: 既存研究では、GA最適化により消去数+60%以上の大幅増が得られた。今回もT-Spin狙いや低層維持強化で**数十％規模の改善**を見込む。小さい違いでも、Top-out率の低下（例: 5%低減）などがあれば実戦上有効と判断する。  
- **可視化と分析**: 各実験結果はボックスプロットやスコア分布図で可視化し、変化パターンを解析。異なる重みセットや特徴量構成の影響をグラフ化して学習過程を解釈する。

## 8. 移行計画とロールバック基準  
既存の20特徴量ベースから新25特徴量モデルへの移行は段階的に行う。具体手順例：  
1. **安全環境での仮評価**: シミュレーション上でまず25特徴量モデルを単独テストし、致命的バグや極端な挙動がないか確認。  
2. **並行運用**: 旧モデルと新モデルの両方でAIを走らせ、結果を比較する。一定期間内に新モデルが**全指標で同等以上**となれば本稼働候補とする。  
3. **漸進的導入**: ユーザテストでは、A/Bテスト（新機能β版）形式で少数プレイヤーに適用し、パフォーマンスと安定性を検証。問題がなければ対象を広げる。  
4. **完全切り替え**: 旧モデルより明確な改善が確認できた段階で、新モデルを標準とする。旧モデルは一定期間アーカイブし、万一のロールバック要因に備える。  

**ロールバック基準**: 新モデルが以下のいずれかに該当した場合、旧モデルに戻す：  
- 全体スコアで有意な性能低下（例: 平均ライン数が旧比-5%以上かつp<0.05）。  
- Top-out率やTop-out回数が増大した場合。  
- 特定の重要指標（T-Spin率、B2B継続率など）が30%以上低下した場合。  
- アクションレイテンシの著しい増大（リアルタイムプレイに影響）。  

以上を事前に決定し、実運用時に監視する。

## 10. 上位特徴量の実装例とテスト  
優先度の高い特徴量について、Python（NumPy/PyTorch）での計算例と単体テストコード例を示す。以下はイメージ例であり、実装の骨格として参考にする。  

### (a) Holes (穴数) と Bumpiness (凸凹度)  
```python
import numpy as np

def column_heights(board):
    # board: 20x10 の 0/1 二次元配列（行0が底面）
    heights = np.zeros(board.shape[1], dtype=int)
    # 各列の最上部ブロック高さを取得
    for x in range(board.shape[1]):
        col = board[:, x]
        filled = np.where(col != 0)[0]
        heights[x] = (filled[-1] + 1) if filled.size > 0 else 0
    return heights

def compute_holes(board):
    heights = column_heights(board)
    holes = 0
    # 各列ごとに高さ内の空セルを数える
    for x, h in enumerate(heights):
        if h == 0: 
            continue
        # bottom=0 to height-1
        holes += (h - np.count_nonzero(board[:h, x]))
    return holes

def compute_bumpiness(board):
    heights = column_heights(board)
    # 隣接列の差の絶対値を足し合わせ
    return np.sum(np.abs(np.diff(heights)))

# 単体テスト例
if __name__ == "__main__":
    # 小さい盤面例（4x4）: 1=ブロック,0=空
    board = np.array([
        [1,0,1,0],  # row0 (底)
        [1,1,0,0],
        [0,1,1,0],
        [1,0,0,0]   # row3 (頂上)
    ], dtype=int)
    holes = compute_holes(board)
    bump = compute_bumpiness(board)
    print("Column heights:", column_heights(board))
    print("Holes:", holes, " (期待値 1)")        # テスト期待値=1
    print("Bumpiness:", bump, " (期待値 3)")   # 例: 列高さ [4,3,3,0] -> 差=|4-3|+|3-3|+|3-0|=1+0+3=4?
```
*注1*: 上記例では `board` を逆向きに設定しているのでテスト値は参考例。実際は20行×10列の盤面で関数を呼び出す。  
*注2*: 正常動作の確認として、テスト用盤面に対して手計算した穴数・凸凹度と出力を比較する。  

### (b) Column Height Variance (高さ分散)  
```python
def compute_height_variance(board):
    h = column_heights(board)
    return np.var(h)

# 単体テスト例
board = np.array([
    [1,1,0],  # 例: 高さ [1,2,0]
    [0,1,0],
    [0,0,0]
], dtype=int)
print("Heights:", column_heights(board))
print("Variance:", compute_height_variance(board), " (期待値 ≈0.667)")
```

### (c) T-Spin Slot Count (T-Spin候補数)  
```python
def count_tspin_slots(board):
    # 簡易例: 縦3マスx横3マス領域で、T字ミノが回転可能な穴数を数える
    spins = 0
    for x in range(1, board.shape[1]-1):
        for y in range(board.shape[0]-2):
            # Tスロットの典型条件(両脇壁＆下が空き or 上空)をチェック
            if (board[y, x-1] == 1 and board[y, x+1] == 1 and board[y+1, x] == 0 
                and board[y, x] == 0):
                spins += 1
    return spins

# 単体テスト例
board = np.array([
    [1,1,1],
    [1,0,1],
    [1,1,1]
], dtype=int)
print("T-Spin slots:", count_tspin_slots(board), " (期待値 1)")
```

上記のコードはあくまで**例示的な実装**であり、実システムでは**高度に最適化・拡張**した形にする。特にPyTorchで実装する場合、特徴量計算部分は可能な限り**行列計算**にし、バッチ処理で並列化するとGPU実装が容易になる。
